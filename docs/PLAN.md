# 원상봇 (wonsang_bot) — 개발 계획서

> 업비트·빗썸 **원화(KRW) 신규상장 따리**를 노리는 자동화 봇.
> 상태: **설계/계획 단계**. 본 문서는 살아있는 문서로, 결정이 바뀌면 같이 갱신한다.

---

## 1. 목표

- **단기:** 원화상장 따리 참여자가 적어 종종 좋은 수익이 나는 지금, 감지→판단→매수처 산정→매도/정리까지의 워크플로를 자동화·반자동화한다.
- **장기:** 불장에서 상장 따리 기대수익이 커질 때, 이미 검증된 봇으로 높은 수익률을 노린다.
- **운영 원칙:** 자금이 움직이는 행위(특히 CEX 출금)는 **보안 우선 → 수동 실행**. 자동화는 "추천 → 반자동(원클릭 확인) → 자동" 순서로 단계적으로 올린다.

---

## 2. 따리 메커니즘 (전략 가정)

상장 따리 = **국내(업비트/빗썸) 상장 직후 발생하는 가격 갭(코프, kimchi premium)** 을 먹는 플레이.

기본 플로우:
1. 국내 거래소 상장 공지 감지 → 상장 코인·컨트랙트 특정.
2. 성공 가능성(갭이 크게 벌어질지) 등급 예측.
3. 해외 CEX/DEX에서 미리 싸게 매집 → **국내 거래소가 입금 지원하는 네트워크로** 보유.
4. 상장 시점에 국내로 입금(출금은 수동) → 국내 가격이 해외보다 비쌀 때 매도.
5. (헤지) 현물 매집과 동시에 해외 선물 공매도로 갭을 고정했다가, 코프가 벌어졌을 때 양쪽을 정리.

핵심 변수:
- **갭 크기 = 국내 수요(상장 펌핑) − 입금 가능 매도 물량(공급).**
- 공급이 막혀 있을수록(빗썸 출금한도, 출금 미지원 네트워크, 락업/베스팅) 갭이 커진다.

## 3. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 언어/런타임 | **Python 3.11**, asyncio | I/O 병렬·저지연 폴링 |
| HTTP | aiohttp / httpx | 공지 폴링, REST |
| CEX 추상화 | **ccxt / ccxt.pro** | 통합 주문·오더북·입출금 메타데이터 |
| 온체인 (EVM) | **web3.py** + RPC(Alchemy/Infura) + Etherscan 계열 API | 토큰 메타·팀물량·전송 추적 |
| 온체인 (Solana 등) | solana-py / solders, Jupiter | 멀티체인 확장 |
| DEX 견적 | 1inch / 0x / Jupiter (애그리게이터) | "가장 유리한 곳" 산정 |
| 브릿지 | LI.FI / Socket(Bungee) / Across / deBridge API + web3 직접 호출 | 프론트 없으면 컨트랙트 직접 호출 |
| 텔레그램 | aiogram(봇 제어) + telethon(채널 수집) | UI·제어판 + 아이디어 수집 |
| X(트위터) | API v2 / 대체 수집 | 언급량 측정 |
| 시세 데이터 | CoinGecko / CoinMarketCap | 시총·해외가·컨트랙트 매핑 |
| LLM | **Claude API (최신 모델)** | 공지 파싱·내러티브 태깅·아이디어 추출 |
| 저장소 | SQLite → PostgreSQL, 시계열은 Parquet | 과거 케이스 DB·스냅샷 |
| 설정/시크릿 | pydantic-settings + `.env`(커밋 금지) | 키 분리·최소권한 |
| 테스트 | pytest + 녹화 픽스처 | 라이브 망 차단 환경 대응 |
| 배포 | systemd/supervisor, Docker | 국내 IP 필요 가능성(공지 폴링) |

## 5. 모듈 상세 (기능 1~8 매핑)

### (1) detector — 원화상장 감지
- **목적:** 업비트·빗썸 공지 게시 즉시 상장 코인과 **컨트랙트 주소**를 특정.
- **구성:** `sources/upbit.py`, `sources/bithumb.py`(공지 API/피드 저지연 폴링·diff), `parser.py`(심볼·마켓·컨트랙트 추출), `events.py`(`ListingDetected` 이벤트 발행).
- **컨트랙트 특정 로직:** ① 공지 본문에 컨트랙트/네트워크가 있으면 직접 파싱 → ② 없으면 심볼→컨트랙트 매핑(CoinGecko/CMC) 후 **체인·프로젝트명 교차검증으로 동일 티커 충돌 방지** → ③ LLM 보조 파싱.
- **난제:** 사전공지(컨트랙트 미포함), 멀티체인 토큰, 동명 티커, 저지연 경쟁(서브초 폴링·ETag/last-id diff·이중화·국내 IP).
- **출력:** `ListingDetected(symbol, contracts[], chains[], market, ts, source, raw)`.

### (2) predictor — 등급 예측 (대성공/성공/보통/실패/큰실패)
- **피처 추출기(`features/`):**
  - `marketcap` 유통 시총(MC) — CoinGecko/CMC + 온체인 유통량 계산.
  - `timing` 상장 시간대 점수 — 금요일 저녁/예상 밖 타이밍 가중.
  - `supply_distribution` 공급 분포 — **빗썸(출금한도) 등 묶인 물량 vs 출금 가능 물량**, 거래소 지갑 클러스터링.
  - `social` 텔레그램·X 언급 빈도/속도.
  - `narrative` 내러티브 태깅(AI/RWA/밈 등) × 현재 핫 내러티브 가중.
  - `onchain_team` 팀·재단 지갑 식별, 베스팅, 최근 출금 → 매도 압력 추정.
  - `tokenomics` 언락 스케줄·FDV/MC → 매도 압력.
- **`scoring.py`:** 투명·조정가능한 가중합 → 등급. (가중치는 기능 8로 갱신)
- **`historical.py`:** 과거 상장 케이스 DB와 **유사 케이스 비교(최근접 이웃)로 2차 검증**, 실현 결과로 가중치 캘리브레이션.
- **선행 과제:** 과거 상장 데이터셋 백필(공지+가격 액션+피처) — 별도 서브프로젝트.
- **출력:** 등급 + 피처별 근거 + 신뢰도 + 비교 케이스.

### (3) buyrouter — 구매처 산정 (CEX/DEX)
- **`networks.py`:** **(업비트/빗썸이 입금 지원하는 네트워크) ∩ (소스 거래소/DEX가 출금/사용 지원하는 네트워크)** 교집합 계산.
- **`cex_router.py`:** 해당 토큰 상장 CEX별 오더북으로 **$10,000 시장가 매수 시뮬레이션(수수료·슬리피지 포함) → 실효가** 산출, 출금 가능성·수수료·소요시간까지 합산해 랭킹.
- **`dex_router.py`:** 도달 가능 체인에서 애그리게이터 견적(가스 포함) → CEX와 비교.
- **`bridge_router.py`:** 최적 유동성이 국내 입금 미지원 체인에 있으면, 국내 입금 지원 체인으로 **브릿지 경로 탐색·총비용(매수+브릿지+수수료+시간/리스크) 비교**.
- **`recommend.py`:** CEX/DEX/브릿지 경로 통합 랭킹 → "**$10k 기준 최적 매수처**" + 비용 분해 제시.
- **확장:** `executor.py` 자동매수(게이트·수동확인 우선 → 점진 자동화).

### (3-b/4 보조) bridge — 내부 브릿지 실행 프로그램
- **목적:** 프론트가 없는 브릿지를 **web3로 컨트랙트 직접 호출**(승인·슬리피지·상태 폴링)하여 사내에서 사용.
- 애그리게이터 라우트 데이터 기반 EVM 우선, Solana(Jupiter/Wormhole/Mayan 등) 확장.

### (4) transfer — 옮기기
- **CEX 출금은 보안상 항상 수동.** 모듈은 출금 정보(네트워크·주소·메모/태그·금액·수수료)와 **체크리스트/알림만 준비**, 실행은 사용자.
- 입금 주소 소유·네트워크 일치 검증으로 오입금 방지.

### (5) seller — 판매하기
- **목적:** 상장 후 입금량을 고려해 적정 매도 가격 제시.
- **기본 룰:** 국내가 ≥ **해외가 +1.5%** 이면 전액 매도(목표). 오더북 깊이·보유량 고려한 분할/지정가 제안.

### (6) liquidator — 정리봇 (on/off)
- **목적:** 직접 못 파는 상황 대비, 상장되면 자동 매도. 기본: 국내가 ≥ 해외가일 때 매도.
- **현물-선물 모드:** 현물 보유 거래소 + 선물(공매도) 거래소를 **쌍으로 선택** → 양쪽 물량 확인 → 지정 조건(코프 = 현·선 갭 확대)에서 **현물 매도 + 선물 숏 정리**를 함께 실행. 포지션 동기화·순차 실행·정합성 검증.
- **현물 모드:** 코프 발생 시 현물 전량 정리.
- **안전장치:** 이미 입금된 자산만 매도, 출금은 절대 안 함.

### (7) basisplay — 현선갭 플레이
- (6) 기반. 거래소별 **현·선 갭 실시간 표시**, **어디서 잡는 게 가장 유리한지** 추천, 임계값 설정 → 정리할 만한 갭 도달 시 **자동 정리 + 알림**. 진입(선물 숏)은 자동화 가능, 현물은 수동/입금분.
- 본질적으로 베이시스/코프 차익 엔진.

### (8) knowledge — 텔레그램 아이디어 수집·반영
- **`ideas.py`:** 텔레그램으로 입력한 아이디어 → 후보 룰/피처/가중치 변경안으로 구조화 → **사람 승인 후** predictor에 반영(버전 관리·리뷰).
- **`tg_ingest.py`:** 채널 링크 제공 시 telethon으로 메시지 수집 → 따리 관련 정보·휴리스틱 추출(LLM) → 갱신안 제안.

## 6. 데이터 모델 (초안)

- `listings` — 감지된 상장(거래소, 심볼, 마켓, 컨트랙트들, 체인들, 공지 ts, raw, 등급, 근거).
- `cases` — 과거 케이스(상장 메타 + 상장후 가격 액션 + 실현 결과 라벨).
- `features_snapshots` — 상장 시점 피처값(재현·캘리브레이션용).
- `venues` — 거래소/DEX/체인별 입출금 네트워크·수수료·한도.
- `quotes` — $10k 견적 스냅샷(경로별 실효가).
- `positions` — 현물/선물 포지션·헤지 쌍·정리 상태.
- `ideas` — 아이디어/제안 변경·승인 이력.

## 8. 보안 · 리스크 · 운영

- **시크릿:** `.env`/시크릿 매니저, 절대 커밋 금지. CEX API 키는 **거래 전용·출금 비활성·출금 주소 화이트리스트**.
- **출금:** CEX→국내 출금은 **항상 수동**(피싱/탈취 방지).
- **자동 실행 게이트:** 자금 이동 기능은 dry-run → 수동확인(원클릭) → 자동, 단계별 한도/킬스위치.
- **리스크:** 거래소 ToS·레이트리밋·IP 차단(공지 폴링은 국내 IP/프록시 필요 가능), 저지연 경쟁, 다거래소 계좌·자본 분산, 멀티체인 오입금, 세무/규제(국내).
- **모니터링:** 헬스체크·지연·실패 알림, 모든 자금 관련 액션 로깅·감사.

## 9. 이 환경의 제약

- 현재 원격 개발 환경은 **아웃바운드 네트워크가 차단**(업비트/빗썸/코인게코 403). → *여기서는* 코드 작성·구조 설계·**녹화 데이터 기반 테스트/백테스트**만 가능.
- 라이브 감지·거래는 **네트워크 정책 허용** 또는 **국내 IP를 가진 별도 서버**에서 실행해야 한다.
